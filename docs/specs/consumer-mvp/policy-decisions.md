# Consumer MVP 정책 결정

> 상위 문서: [Consumer MVP API 명세](../consumer-mvp-api-spec.md)  
> 성격: 회의에서 확정한 제품 정책. API 필드나 DB 모델의 근거로 사용하지 않는다.

## 주문 흐름

- 후결제 방식이다: 메뉴 선택 → 장바구니 → 주문 → 퇴장 시 직원 결제.
- 회원가입·로그인과 온라인 결제는 제외한다.
- 같은 테이블에서 여러 번 추가 주문할 수 있다.
- 추가 주문 전용 버튼은 두지 않는다. 주문 성공 후 비워진 장바구니에서 다시 주문한다.
- 소비자가 이전 주문을 직접 수정하거나 취소하지 않는다. 직원에게 요청한다.
- 소비자 화면은 주문 성공 시 “주문이 접수되었습니다”만 표시한다.
- 주문 완료 화면의 최종 표시 모델은 아직 결정하지 않았다.

## 주문 상태와 결제

- 기존 주문 상태 코드를 재사용하며 Consumer 전용 상태 코드는 만들지 않는다.
- 흐름은 주문 접수(`01`) → 조리 중(`02`) → 서빙 완료(`03`) → 결제 완료다.
- 접수·조리·서빙 상태에서 직원이 주문을 취소할 수 있다.
- 직원이 실제 결제가 끝났다고 보고 결제완료를 기록한다.
- 고객 결제 승인, 실패, 환불, 결제 취소, 영수증 발급은 프로젝트 범위 밖이다.
- 결제완료 DB 상태를 방문 종료의 기준으로 사용한다. 종료 직후 UX는 추가 결정이 필요하다.

## QR과 세션

- QR에는 `/qr/{ULID}`가 들어간다.
- 백엔드가 QR·테이블을 검증하고 `qrTableInfo` 서버 세션을 만든다.
- 새로고침 후에도 테이블 정보를 복구할 수 있어야 한다.
- 개인이나 기기를 별도 식별하지 않는다.
- QR 세션은 매장·테이블을 식별하고 주문번호는 개별 주문을 식별한다.
- 주문 전 5분 동안 조작이 없으면 Consumer 바인딩을 만료한다.
- 주문이 생성된 방문은 5분 만료의 예외이며 결제완료까지 유지한다.
- 복사한 QR의 매장 외부 주문 차단 방식은 보류한다.

## 같은 테이블 공유와 동시성

- 같은 테이블의 같은 방문 고객은 서로의 확정 주문내역을 볼 수 있다.
- 여러 고객의 동시 주문을 허용한다.
- 다른 고객의 확정 주문은 내 편집 가능한 장바구니 항목과 구분해 표시한다.
- 프런트는 주문 제출 중 버튼을 비활성화한다.
- 주문 성공 시 요청한 고객의 장바구니를 비우고 공유 주문목록을 갱신한다.
- 백엔드는 같은 요청의 중복 생성을 차단하고 같은 테이블 동시 요청을 안전하게 순서 처리한다.
- 중복 판정 시간 `N`초와 다중 서버 저장 방식은 미결정이다.

## 메뉴와 옵션

- 판매 중지 메뉴는 숨긴다.
- 품절 메뉴는 표시하지만 선택할 수 없다.
- 이미지가 없으면 placeholder를 표시한다.
- 카테고리와 메뉴는 `ordNo` 순서로 표시한다.
- 필수 옵션 여부를 표시하고 미선택 시 장바구니에 담을 수 없다.
- 수량형 옵션은 `maximumNum` 이내에서 중복 선택할 수 있다.
- 메뉴별 최대 수량은 UI에서 제한하고 메뉴 데이터 제공 방안은 후속 검토한다.
- 한정수량 기능의 구체 모델은 아직 결정하지 않았다.

## 가격과 변경

- 프런트는 예상 금액을 표시한다.
- 백엔드는 주문 확정 시 현재 메뉴·옵션·가격·품절 상태를 다시 검증하고 최종 금액을 계산한다.
- 화면 가격과 서버 확정 가격이 다르면 주문 전에 변경 내용을 안내한다.
- 회의의 “결제 시 기준 보존”과 “기존 QR 사용자가 모두 나간 뒤 변경 적용”은 정책 방향이다.
- 위 정책의 가격 버전·저장 방식은 결정되지 않았으며 API 모델이나 DB 컬럼을 추론해 추가하지 않는다.

## 장바구니

- 같은 메뉴와 같은 옵션 조합은 한 줄로 합친다.
- 옵션 조합이 다르면 별도 줄로 둔다.
- 새로고침이나 브라우저 재실행 후에도 유지한다.
- 매장 또는 테이블이 바뀌면 기존 장바구니를 삭제한다.
- 품절·가격 변경 항목은 자동 삭제하지 않고 사용자가 확인하도록 한다.

## 실시간 갱신

- Consumer SSE를 사용하기로 했지만 구현은 마지막 순서다.
- SSE 전에도 주문 생성 성공 여부는 HTTP 응답으로 확정한다.
- 소비자에게 조리 단계 전체를 실시간 표시하는 기능은 현재 범위가 아니다.
- 현장 주문 취소 안내는 직원이 직접 한다.

## 보류 항목

- 결제완료 직후 화면 전환과 새 방문 생성 시점
- 외부 복사 QR 차단 신호
- 주문 완료 화면 데이터 모델
- 중복 요청 차단 시간 `N`
- 메뉴별 최대 수량과 한정수량 API 필드
- 가격 변경을 방문 종료 뒤 적용할 저장·버전 전략
