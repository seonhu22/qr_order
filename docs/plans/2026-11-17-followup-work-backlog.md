# 후속 작업 / 알림과 실제 서버 자동 QA

기준일: 2026-11-17. 근거: 사용자 요청과 승인. 구현 계획이나 API 계약 확정 문서가 아니라 후속 요구사항 목록이다.

기존 [프로젝트 마감 TODO](./2026-11-10-project-closeout-backlog.md)와 [프론트 TODO](../../frontend/docs/todo.md)를 보완한다. 현재 요청에서는 구현과 실제 서버 테스트를 시작하지 않는다.

## 1. 공지사항 알림 연결

- 사용자 제공 현황: 알림 mock 데이터와 UI가 구현되어 있다. 코드 연결 여부는 후속 조사 대상이다.
- 요구: 공지사항 생성 시 지정 대상에게 알림을 제공한다.
- 수신 대상: Client 관리자만 / 스태프만 / 모두.
- 후속 확인: 기존 공지 대상 필드, 실제 알림 API, 매장 범위, 읽음 처리, 생성 후 갱신 방식.
- 기존 관리자 알림 작업과 중복 여부를 먼저 확인한다. 새 저장 구조나 SSE 계약은 아직 확정하지 않는다.

## 2. 실제 서버 자동 QA 설정

- 승인: 별도 DB 대신 전용 테스트 매장과 기존 계정을 사용한다.
- 승인: 해당 매장에서 테스트에 필요한 생성/수정/취소/결제/미결제를 수행할 수 있다.
- 데이터는 남아도 되지만 입력 가능한 이름/설명에 `AUTO-QA`와 실행 식별자를 남긴다.
- 메모 필드가 없는 작업은 테스트 매장과 실행 기록으로 식별한다. 식별 방법이 없는 쓰기는 실행 전에 확인한다.
- 계정은 Git 제외 로컬 환경변수 파일에 직접 입력한다. 비밀번호는 채팅/커밋/실행 로그에 남기지 않는다.
- 사용자 보고: 환경변수 파일 작성 완료. 실제 파일 로딩/필수 변수/로그인 검증은 아직 수행하지 않았다.
- 로그인 직후 실제 매장과 역할을 검사한다. 중복 아이디로 예상 계정과 다르면 쓰기 전에 중단한다.
- 초기 실행은 순차 실행/최소 재시도로 구성한다. 대량 실행 전 예상 작업량을 알리고 반복 서버 오류/지연 시 중단한다.
- DB 초기화는 별도 합의 대상이며 자동 실행하지 않는다.
- 다음 준비: 입력 예시/환경 검사/실행 명령/실패 trace/테스트 데이터 식별 방식.

## 3. 관리자와 스태프 대시보드 / 후순위

- Client 관리자: 공지사항/결제/정산 등 섹션을 커스터마이징하는 대시보드가 목표다.
- 스태프: 배치된 테이블별 주문 메뉴를 확인하고, 테이블 클릭으로 정산 흐름에 진입하는 것이 목표다.
- 후속 확인: 기존 랜딩페이지/테이블 배치/결제 화면 재사용 범위와 역할별 권한.
- 섹션 저장 방식과 UI/API 계약은 별도 설계 때 확정한다.

## 4. 공통코드 연결 현황 보고

- 화면별 고정 선택값과 공통코드 조회/저장 연결 여부를 조사한다.
- 보고는 연결 완료 / 하드코딩 / 미연결 / 사용자 코드 등록 필요로 구분하고 파일/API 근거를 남긴다.
- 기존 공통코드 후속 항목과 대조한다. 조사 전 완료 여부를 단정하지 않는다.

## 5. 사용자 관리 API와 신규 스태프 표시

- 사용자 관찰: 신규 스태프를 추가해도 UI 목록에 보이지 않는다. 재현과 원인 확인이 필요하다.
- 추가 DB 관찰(사용자 보고): 관리자 회원가입으로 생성된 `sys_user`는 `plant_cd`만 채워지고, 관리자 로그인 후 추가한 스태프는 `sys_plant_cd`만 채워진다.
- 중점 조사: 두 컬럼의 실제 의미와 가입/스태프 생성 INSERT, 로그인 세션의 매장 매핑, 목록 조회 WHERE/JOIN이 사용하는 컬럼을 대조한다. 저장 차이가 목록 누락의 원인인지는 아직 미확정이다.
- 두 컬럼을 임의로 복사하거나 기존 데이터를 일괄 수정하지 않는다. 계약 확인 후 수정 범위와 기존 데이터 보정 필요 여부를 판단한다.
- 조사 순서: 생성 요청/응답 → 저장 결과 → 목록 응답 → 매장/역할 필터 → query key와 캐시 무효화 → 화면 표시.
- 중복 아이디와 로그인된 실제 매장도 함께 확인한다. 서버/프론트 어느 쪽 문제인지 아직 확정하지 않는다.
- 사용자 결정: 본인의 비밀번호 초기화는 의도된 기능이므로 유지한다.
- 기존 본인 변경/초기화 API와 관리자에 의한 타인 초기화를 구분해 확인한다. 이번 기록만으로 권한 검사를 완화하지 않는다.
