# Client 메뉴 관리 프론트 권한 검증

## 근거와 범위

- 사용자 결정: 메뉴 관리는 관리자만, 다른 업무는 기존 권한 유지.
- 기존 `ClientRoutes`에는 로그인 확인만 있었고 두 메뉴 관리 경로에 업무 권한 가드가 없었다.
- 인증 계약은 `role`과 `staffRole`을 구분한다. 실제 `AuthApiController`도 DB 업무 권한을 `staffRole`로 응답한다.
- 프론트 범위만 수정했다. 서버 인가/DB 스키마/API DTO/생성 타입은 변경하지 않았다.

## 학습용 커밋 순서

아래 순서로 한 커밋씩 `git show 커밋번호`를 읽는다. 같은 기능을 함수 → 메뉴 → 로그인 연결 → 가드 → 라우트 순으로 쌓았다.

1. `507e17a8`: 접근 판정 함수와 정책 테스트.
2. `792bd837`: 서버/기본 메뉴에서 권한 없는 항목 필터.
3. `892ca223`: 현재 로그인 `staffRole` 연결과 역할 전환 테스트.
4. `468d49f6`: 보호 페이지보다 먼저 실행되는 가드.
5. `1bdd577e`: 두 메뉴 관리 라우트에 가드 연결.
6. `e2c905ac`: 실제 브라우저 관리자/스태프 회귀.
7. `f560d4d9`: URL 대소문자/인코딩 우회 방어.
8. `dc0f8d81`: 필터 단계를 읽기 쉽게 분리하고 결과 타입 명시.
9. `1b1d70df`: 사용 정책과 수동 QA 대기 기록.

## 왜 이렇게 수정했나

- `getAuthUserStaffRole`을 재사용했다. 전역 ADMIN 권한과 Client 관리자 권한은 같은 필드가 아니다.
- 메뉴 카탈로그 생성 후 필터한다. 필터 결과가 비었다고 정적 fallback을 다시 적용하면 금지 메뉴가 복원될 수 있다.
- 가드를 pathless 그룹에 둔다. 메뉴를 숨겨도 직접 입력한 URL은 별도 차단해야 한다.
- 최초 URL 문자열 판정은 대문자 URL에서 우회됐다. 실제 Chromium 실패를 확인하고 그룹 진입 시 무조건 역할을 검사하도록 바꿨다.
- 권한을 별도 state/effect에 저장하지 않고 현재 인증 값에서 계산한다. 계정 전환 시 오래된 값이 남지 않도록 한다.
- 직원호출은 보호 그룹 밖에 유지한다. 메뉴 섹션에 있다는 이유만으로 확정되지 않은 업무 권한을 추가 제한하지 않는다.

## 검증

- 판정/메뉴 필터의 역할 누락/유사 경로/서버 메뉴 코드 변경/정적 fallback/URL 정규화 테스트 통과.
- 로그인 연결/Sidebar/Layout 관련 3개 파일/16개 테스트 통과.
- 가드 4개 테스트 통과. 관리자만 보호 콘텐츠 렌더링.
- 권한 브라우저 5개 통과(47.2초). 관리자 조회/스태프 API 무요청/URL 변형 차단.
- 읽기전용 보안 검토: 수정 요구 결함 없음. 실행 테스트와 서버 검증 한계는 별도 유지.
- 최초 전체 검증은 151개 파일에서 651개 통과/기존 관리자 알림 1개 실패였다. 타입/lint/E2E 타입/브라우저 13개/build는 통과했다. 실패 실행도 성공으로 보고하지 않는다.
- 알림 테스트는 Query 데이터 수신을 먼저 확인하고 실제 상단 헤더 내부에서 버튼을 찾도록 보완했다. 사이드바에도 header가 있어 `banner`가 하나라고 가정하지 않았다. 타임아웃/업무 코드/검증 조건은 완화하지 않았다.
- 후속 Client 안내 변경을 포함한 최종 `npm run verify` 종료 코드 0. 스크립트 6개/153파일의 단위 테스트 674개/브라우저 14개/일반과 E2E 타입/lint/build 모두 통과했다.
- 최종 증거: `frontend/src/test/test-result/verify-2026-11-11-050528-975-7684/summary.md`. 원본 로그/JSON은 Git에 올리지 않는다.

## 남은 한계

- 브라우저 가드는 직접 API 호출을 차단할 수 없다. 백엔드 메뉴 API 인가 미완료 상태를 유지한다.
- 실제 관리자/직원 세션과 계정 전환은 [일괄 QA](../../frontend/docs/todo.md#일괄-수동-qa-대기-목록)에 기록했다.
- 원격 CI/push/공유 DB 변경은 하지 않았다. 로컬 검증 통과를 배포 완료로 표현하지 않는다.
