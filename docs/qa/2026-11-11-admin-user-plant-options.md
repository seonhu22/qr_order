# 관리자 사용자 사업장 선택 검증

## 근거와 변경 이유

- 실제 선택지는 `/api/combo/plant`이다. [Combo SQL](../../qrorder/src/main/resources/mapper/common/ComboMapper.xml)은 사용 중이며 삭제되지 않은 사업장을 조회한다.
- 기존 프론트는 빈 응답을 관리자/강남점/판교점/성수점으로 대체했다. 실제로 존재하지 않는 사업장을 저장할 위험이 있어 대체 목록을 제거했다.
- 빈 목록이라고 기존 사용자의 사업장까지 지우면 안 된다. 기존 저장값은 해당 행에서만 비활성 선택지로 표시하고 신규 행에는 제공하지 않는다.
- 신규 행은 실제 API 선택지에 포함된 코드만 저장 검증을 통과한다. 기존 행 수정은 저장된 코드를 보존한다.
- DB/백엔드/API 계약을 추가하지 않고 기존 조회 계약을 사용했다.

## 커밋을 읽는 순서

1. `0ea8fda0`: 가짜 목록 제거/API 빈 응답 테스트.
2. `a51abf7e`: 기존 사업장 표시 보존/UI 테스트.
3. `a3894459`: 신규 행의 코드 유효성 검증/상태 테스트.
4. `1df12001`: 기존 코드의 실제 HTTP 저장 요청 보존 테스트.

가짜 목록만 담은 `constants.ts`를 삭제했다. 실제 데이터 삭제는 없으며 이전 파일은 Git 이력에 남아 있다.

## 검증 결과

- 변경 전 가짜 목록 반환/기존 표시 소실/목록 밖 신규 코드 허용을 테스트로 각각 재현하고 수정 후 통과했다.
- `npm test -- --run src/apps/admin/features/admin-user --reporter=default --reporter=json --outputFile=src/test/test-result/admin-user-plant-final.json`: 5개 파일/19개 테스트 통과.
- `npm run typecheck`, `npm run lint`, `npm run build -- --logLevel error`: 모두 종료 코드 0.
- 읽기전용 독립 검토: 수정 요구 결함 없음. 행별 선택지와 비활성 항목의 선택 차단 확인.
- 직전 전체 검증은 단위 테스트 674개/브라우저 14개 통과했다. 이번 사업장 변경 이후에는 관련 19개와 타입/lint/build를 실행했으며 전체 테스트를 다시 실행했다고 주장하지 않는다.

## 계약 경계와 남은 QA

| 경계 | 확인 상태 |
| --- | --- |
| DB 제약/영속 SQL/백엔드 DTO | 기존 조회 SQL 읽기 확인/변경 없음 |
| OpenAPI/생성 타입 | 변경 없음 |
| 프론트 응답 매퍼/행 모델 | 자동 테스트 검증 |
| 요청 매퍼/HTTP 직렬화 | MSW로 실제 전송 본문 검증 |
| DB 기반 저장 성공 | 미검증 |
| dev:real 수동 QA | 대기 |

실제 서버에서 빈 목록/조회 실패 시 가짜 지점이 없는지, 신규 행의 정상 사업장 선택/저장, 기존 사용자의 이름만 수정한 후 사업장 코드가 보존되는지 확인한다. 공유 DB 수정이나 원격 push는 수행하지 않았다.
