## 신규 후속 요구사항

공지 대상별 알림의 SQL/코드는 작성됐으며 실제 DB 적용과 역할별 수동 QA가 남았다. [적용 순서와 QA](../../docs/qa/2026-11-18-notice-audience-integration.md)를 기준으로 진행한다.

공지사항 대상별 알림/실제 서버 자동 QA/역할별 대시보드/공통코드 연결 조사/신규 스태프 목록 누락은 [2026-11-17 후속 작업 목록](../../docs/plans/2026-11-17-followup-work-backlog.md)에서 관리한다. 요구사항 접수 상태이며 구현 완료를 뜻하지 않는다.

- 정책과 검증 근거: [관리자 알림](./page/manager-notifications.md).

## 계약 확인 후 재개할 작업

- 사용자 관리 권한 보완은 구현/자동 검증 후 위 USER-01 실제 서버 QA로 이동했다. 승격 전용 Admin UI/강등/매장 이전은 별도 범위다.
- 공통코드: 실제 마스터 코드/등록 상세값 확인 후 연결.
- 관리자 알림 서버 읽음: 브라우저 로컬 방식으로 우선 연결. 기기 간 동기화는 서버 저장 계약 확정 후 진행.
- 사업장: 일반 가입 사업장명/계정 이메일과 사업장 이메일 관계 확인.
- 자동 E2E: 모의 API 기반 핵심 회귀와 관리자 알림/주문 수정/SSE/문의 파일 시나리오를 관리한다. 실제 서버 저장까지 검증할 전용 QA 계정/데이터는 후속으로 준비한다. [실행 안내](./testing/browser-e2e.md).
- CI: 저장소 workflow에 전체 테스트/lint/브라우저 회귀 job 연결. GitHub 원격 실행과 required check 설정 확인은 사용자 push 후 진행한다. [검증 기록](../../docs/qa/2026-11-10-frontend-quality-automation.md).
- 근거와 재개 조건: [마감 작업 확인 항목](../../docs/qa/2026-11-10-closeout-followups.md).

검증 실행과 실패 로그 수집은 `npm run verify`로 묶었고 최종 7개 검사를 모두 통과했다. [결과 확인](./testing/verification.md), [검증 보고서](../../docs/qa/2026-11-11-verification-automation.md). 모의 API 자동화는 위 실제 서버 수동 QA 완료를 의미하지 않는다.

후속 작업도 구현/자동 검증 후 이 섹션에 추가하고, 수동 통과 시 결과 문서에 날짜와 관찰 근거를 남긴 뒤 [완료 기록](./completed.md)으로 이동한다.
